Single-file public API in `src/router.ts` that owns a singleton `WasmRouter` instance (from `src/pkg/wheels_router_nano.js`, generated by wasm-pack) plus its `wheels_router_nano_bg.wasm` binary. `initRouter(dataUrl?)` lazily initializes the WASM module and tries a cascade of graph sources: local `data/hk.wheelsrouter.gz`, the supplied URL, then remote `hk-gtfsdata.morgandev.cc` URLs, caching the first successful load. The router exposes typed interfaces (`RouteQuery`, `Plan`, `Leg`, `RouteOption`, `StopInfo`, `RankContext`, `PlanBreakdown`) and pure functions layered on top of raw WASM plans: mode classification (`isMtrTransitOption`, `isBusTransitOption`, `classifyTrafficMethodId`), filter enforcement (`planMatchesFilters` using traffic-method and bus-company allowlists), plan analysis (`analyzePlan` counting transfers, LRT/MTR/bus legs, free interchange walks, street walks), and human-centric scoring (`perceivedCost` blending fastest/simplest/cheapest preferences via weighted penalties). Domain helpers are imported from sibling modules (`mtrColors`, `mtrInterchange`, `harbourWalk`, `stationAccess`, `shuttleInject`, `alightPrefer`) — this module is the composition layer that turns raw RAPTOR output into ranked, filtered HK transit plans.
