Four sibling modules form a small data layer for two transit modes. `lrtStops.js` is a static registry of ~80 LRT stops (WGS84 coords, official stop codes/IDs) that can be mutated at runtime by `applyLrtStopOverrides()` reading `public/overrides/lrt.json`; it also exposes search/matching helpers (`matchLrtStop`, `searchLrtStopsLocal`, `resolveLrtPlatform`). `lrtRouteData.js` lazily loads the MTR Light Rail CSV (`opendata.mtr.com.hk`) through a three-tier fetch strategy — bundled static file → `/eta/mtr-open` proxy → direct URL — parses it with an in-process CSV parser, merges peak-hour-only routes (751P) from `LRT_ROUTE_OVERRIDES`, and caches rows so `ensureLrtRouteData()` returns immediately on repeat calls; it then exposes `lrtRouteDirections()` and `lrtStopSequence(routeId, bound)` which resolve each stop's coordinates back into `LRT_STOPS`. `gmbRouteData.js` is independent: it queries the same-origin `/eta/gmb/*` endpoints to discover region-scoped route codes, direction slots, ordered stop lists, and per-stop WGS84 coordinates, caching results in module-level Maps keyed by route code and `routeId|routeSeq`. `lrtShapes.js` reads platform/shape overrides from `public/overrides/lrt.json` and provides polyline correction functions (`lrtHopOverride`, `getGinzaToTinWingShape`, `tinWingPlatformOverride`) used by map rendering to fix known broken LRT segments. Dependency direction is one-way: `lrtRouteData.js` imports `LRT_STOPS` from `lrtStops.js`; both `lrtStops.js` and `lrtShapes.js` import shared override resolution from `./overrides.js`; `gmbRouteData.js` has no cross-imports within this scope.
