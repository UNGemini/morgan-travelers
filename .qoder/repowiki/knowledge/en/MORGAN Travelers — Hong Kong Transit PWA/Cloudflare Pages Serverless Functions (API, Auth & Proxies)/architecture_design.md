Each directory under `functions/` is a Cloudflare Pages Function mounted at its path via the `[[path]]` catch-all convention. The module splits into two concerns: (1) business endpoints under `api/` — `auth/[[path]].js` implements a GitHub OAuth flow (`/api/auth/github`, `/api/auth/callback`, `/api/auth/me`, `/api/auth/logout`) using signed session cookies stored in `morgan_gh_sess`; `overrides/[[path]].js` proxies `bus-shapes.json` from a configurable GitHub repo; `contribute-path.js` validates incoming draft payloads against the `morgan.travelers.bus-shape.v1` schema, optionally stores them to KV/R2, fires a webhook, and opens a GitHub PR via shared helpers. (2) Thin transparent proxies — `eta/`, `geocode/`, `osrm/` rewrap third-party APIs behind same-origin paths with CORS and short cache headers to satisfy COEP. All handlers share `functions/_shared/github.js`, which centralizes GitHub API calls, base64 encoding, session cookie serialization, and the full `openOverridesPullRequest` workflow supporting both bot-PAT and per-user OAuth modes. Every function exports a single `onRequest(context)` handler and uses the native `fetch`/`Response` Web APIs so the code runs identically on Cloudflare Workers and Node 18+ dev middleware.
